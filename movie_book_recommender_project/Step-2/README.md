**تهیه‌کننده:** ابراهیم یدالهی  
**درس:** آزمایشگاه هوش مصنوعی  
**عنوان پروژه:** سیستم هوشمند پیشنهاددهنده فیلم و کتاب

## 📌 ۱. معرفی و هدف گام دوم

گام دوم پروژه بر مهندسی داده، تدوین طرح‌واره‌های ساختاربافته (Schema)، ممیزی کیفیت داده‌ها و طراحی معماری سیستم متمرکز است. در این مرحله، کاتالوگ آثار چندرسانه‌ای و ماتریس تعاملات کاربر-آیتم آماده‌سازی شده و خط لوله اعتبارسنجی مستقل با تقسیم قطعی آموزش و آزمون (Train/Test Split) بدون نشت اطلاعات (Data Leakage) پیاده‌سازی شده است.

---

## 🗃️ ۲. مشخصات ساختار داده‌ها (Data Schema)

داده‌های سامانه بر اساس سه موجودیت تفکیک‌شده طراحی شده‌اند:

```text
┌─────────────────────────┐               ┌─────────────────────────┐
│       کاربر (User)      │               │       آیتم (Item)       │
├─────────────────────────┤               ├─────────────────────────┤
│ user_id (شناسه کاربر)   │               │ item_id (شناسه اثر)     │
│ preferences (علایق اولیه)│               │ title (عنوان اثر)       │
└───────────┬─────────────┘               │ type (فیلم / کتاب)      │
            │                             │ genres (فهرست ژانرها)   │
            │                             └────────────┬────────────┘
            │      ┌────────────────────────┐          │
            └─────►│   تعاملات (Ratings)     │◄─────────┘
                   ├────────────────────────┤
                   │ user_id                │
                   │ item_id                │
                   │ rating (امتیاز ۱ تا ۵) │
                   │ timestamp              │
                   └────────────────────────┘
```

### شرح فیلدهای داده:

| موجودیت | نام فیلد | نوع داده | توضیحات |
| ---: | ---: | ---: | ---: |
| **User** | `user_id` | عدد صحیح / رشته | شناسه یکتای هر کاربر در سامانه |
| **User** | `preferences` | لیست متنی | ژانرها و موضوعات مورد علاقه اولیه کاربر |
| **Item** | `item_id` | عدد صحیح / رشته | شناسه یکتای هر فیلم یا کتاب |
| **Item** | `title` | رشته | عنوان رسمی اثر |
| **Item** | `type` | دسته‌ای (`movie`/`book`) | نوع رسانه اثر |
| **Item** | `genres` | لیست متنی | برچسب‌های موضوعی و ژانرهای منتسب به اثر |
| **Rating** | `rating` | عددی ($1.0$ تا $5.0$) | امتیاز صریح ثبت‌شده توسط کاربر |
| **Rating** | `timestamp` | زمان یونیکس / رشته | زمان دقیق ثبت تعامل برای تفکیک‌های زمانی |

## ⚙️ ۳. مراحل آماده‌سازی و خط لوله ممیزی داده

فرایند اعتبارسنجی داده‌ها در اسکریپت‌های `data_loader.py` و `evaluation.py` به ترتیب زیر اجرا می‌شود:

```text
  ┌───────────────────────┐
  │   داده‌های خام کاتالوگ │
  │    و لاگ تعاملات      │
  └───────────┬───────────┘
              │
              ▼
  ┌───────────────────────┐
  │   پاک‌سازی و فیلتر     │ ◄─── حذف رکوردهای نامعتبر و تکراری
  │   (Data Cleaning)     │
  └───────────┬───────────┘
              │
              ▼
  ┌───────────────────────┐
  │   تفکیک بدون نشت      │ ◄─── جداسازی ۸۰/۲۰ آموزش و آزمون
  │  (Train/Test Split)   │
  └───────────┬───────────┘
              │
              ▼
  ┌───────────────────────┐
  │   ممیزی و آزمون نشت   │ ◄─── سنجش نرخ تخلخل (Sparsity)
  │  (Leakage Validation) │      و بررسی تقاطع تهی Train و Test
  └───────────┬───────────┘
              │
              ▼
  ┌───────────────────────┐
  │  گزارش و ذخیره خروجی  │ ◄─── تولید نمودار و جدول ماتریس تعاملات
  └───────────────────────┘
```

۱. **پاک‌سازی و سالم‌سازی داده‌ها:**
   * بررسی و پالایش مقادیر مفقوده (`NaN`).
   * اطمینان از قرار گرفتن امتیازها در بازه معتبر $[1, 5]$.
   * حذف رکوردهای تکراری در زوج‌های (کاربر، آیتم).

۲. **تفکیک داده‌ها به مجموعه‌های آموزش و آزمون:**
   * تفکیک با نسبت قطعی ۸۰ درصد آموزش (`train.csv`) و ۲۰ درصد آزمون (`test.csv`).
   * تضمین ثبت رفتار ارزیابی منصفانه برای کاربران فعال.

۳. **ممیزی عدم نشت اطلاعات (Data Leakage Audit):**
   * بررسی تقاطع زوج‌های کاربر-آیتم میان مجموعه آموزش و آزمون؛ در صورت وجود حتی یک رکورد مشترک در هر دو مجموعه، آزمون ناموفق گزارش می‌شود:
   $$\text{Train} \cap \text{Test} = \emptyset$$

۴. **محاسبه نرخ تخلخل ماتریس (Sparsity Measurement):**
   * اندازه‌گیری میزان تنکی ماتریس تعاملات برای برنامه‌ریزی روش‌های رفع چالش شروع سرد:
   $$\text{Sparsity} = 1 - \frac{\vert{}\text{Ratings}\vert{}}{\vert{}\text{Users}\vert{} \times \vert{}\text{Items}\vert{}}$$

---

## 🛡️ ۴. ماتریس ریسک و راهکارهای مهار در سیستم

| ریسک / چالش | شرح مسئله | راهکار پیاده‌سازی‌شده در خط لوله |
| ---: | ---: | ---: |
| **شروع سرد (Cold Start)** | نبود اطلاعات کافی درباره کاربر یا آیتم جدید | استفاده از ویژگی‌های محتوایی (ژانر و متادیتا) و خط مبنای محبوبیت هموارشده |
| **پراکندگی داده (Data Sparsity)** | کم‌بودن تعامل‌های ثبت‌شده نسبت به ابعاد ماتریس | سنجش دقیق نرخ تخلخل ماتریس و بهره‌گیری از فضای مشترک محتوا |
| **نشت اطلاعات (Data Leakage)** | ورود داده‌های ارزیابی به مرحله آموزش مدل | تفکیک قطعی و اعتبارسنجی صفر بودن اشتراک زوج‌های کاربر-آیتم |
| **سوگیری محبوبیت (Popularity Bias)** | تمرکز بیش از اندازه به آیتم‌های پرطرفدار | گزارش پوشش کاتالوگ و امکان بازرتبه‌بندی به روش تنوع‌بخشی MMR |
| **تفاوت مقیاس امتیازدهی** | تفاوت دامنه و رفتار امتیازدهی فیلم‌ها در مقایسه با کتاب‌ها | مرکزدهی و نرمال‌سازی درون‌منبعی پیش از ادغام نهایی |

## 🗂️ ۵. ساختار فایل‌ها و خروجی‌های گام دوم

```text
Step-2/
│
├── data/                              # داده‌های استاندارد، مجموعه‌های آموزش/آزمون و نمودارها
│   ├── items.csv                      # فراداده کاتالوگ فیلم‌ها و کتاب‌ها
│   ├── ratings.csv                    # ماتریس کامل تعاملات کاربر-آیتم
│   ├── train.csv                      # ۸۰ درصد داده‌های آموزش بدون نشت
│   ├── test.csv                       # ۲۰ درصد داده‌های آزمون مستقل
│   ├── README.md                      # راهنمای متادیتا، منابع دریافت داده و ستون‌ها
│   └── rating_evaluation.png          # نمودار هیستوگرام توزیع امتیازها و ارزیابی داده
│
├── src/                               # اسکریپت‌های منبع و پردازش داده‌ها
│   ├── data_loader.py                 # ماژول بارگذاری، پاک‌سازی و تفکیک داده‌ها
│   ├── evaluation.py                  # اسکریپت ممیزی، محاسبه Sparsity و تست Leakage
│   └── evaluation.ipynb               # نوت‌بوک جوپیتر گزارش تعاملی و ماتریس تعاملات
│
├── DESIGN.md                          # سند رسمی طراحی معماری سامانه (System Design)
└── README.md                          # شناسنامه فنی و راهنمای خط لوله گام دوم
```

### شرح ماژول‌های پیاده‌سازی‌شده:

| فایل | کاربرد |
| ---: | ---: |
| `src/data_loader.py` | دریافت، پاک‌سازی و تفکیک داده‌ها به مجموعه‌های Train و Test |
| `src/evaluation.py` | بررسی عدم نشت داده، نرخ تخلخل، ماتریس تعاملات و تولید نمودار |
| `src/evaluation.ipynb` | گزارش تعاملی بصری شامل جداول آماری و ماتریس تعاملات |
| `DESIGN.md` | سند طراحی جامع معماری سامانه، روابط ریاضی، طرح‌واره داده‌ها و خطوط مبنا |

## 🚀 ۶. نحوه اجرا و راه‌اندازی خط لوله داده

برای اجرای خط لوله آماده‌سازی داده و انجام ممیزی:

```bash
# مرحله اول: ورود به پوشه گام دوم
cd movie_book_recommender_project/Step-2

# مرحله دوم: اجرای بارگذاری و پاک‌سازی داده‌ها
python src/data_loader.py

# مرحله سوم: اجرای ممیزی، بررسی عدم نشت داده و تولید نمودارها
python src/evaluation.py
```

پس از اجرای موفقیت‌آمیز، فایل‌های مجموعه‌های آموزش و آزمون در پوشه `data/` ذخیره شده و نمودار ارزیابی `rating_evaluation.png` به‌روزرسانی می‌شود.
